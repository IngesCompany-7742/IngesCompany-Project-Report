# Capítulo III: Requirements Specification
En este capítulo se presenta los requisitos especìficados de DoofPlus, acorde al análisis de la problemática, los segmentos objetivo y el alcance obtenido durante el desarrollo. La especificación cubre tres productos de la solución: la landing page pública, la aplicación web frontend y los servicios backend RESTful implementados con una arquitectura basada en bounded contexts.


## 3.1. User Stories

| US02 | Presentación de Características Técnicas y Módulos | Como Visitante interesado en tecnología, quiero explorar las características detalladas del sistema (IoT, Control de Calidad) para entender el alcance funcional de la solución. | **Escenario 1 (Exploración Exitosa - Happy Path):**<br>Dado que el visitante navega hacia la sección de características,<br>cuando selecciona un módulo específico (como Monitoreo IoT),<br>entonces el sistema muestra la descripción técnica detallada y los beneficios de dicho componente.<br><br>**Escenario 2 (Módulo no disponible - Unhappy Path):**<br>Dado que el visitante intenta acceder a la información de un módulo futuro o en mantenimiento,<br>cuando selecciona dicho módulo,<br>entonces el sistema muestra un mensaje de "Próximamente" y sugiere suscribirse al boletín. | EP01 |
| US03 | Formulario de Contacto y Solicitud de Demostración | Como Visitante de un segmento empresarial, quiero enviar mis datos de contacto para solicitar una demostración personalizada del software de producción. | **Escenario 1 (Flujo Exitoso - Happy Path):**<br>Dado que el visitante decide solicitar una demostración,<br>cuando completa el formulario con datos válidos y envía la solicitud,<br>entonces el sistema registra la información del interesado y envía una confirmación automática por correo electrónico.<br><br>**Escenario 2 (Validación de Datos - Unhappy Path):**<br>Dado que el visitante se encuentra completando el formulario,<br>cuando intenta enviar la solicitud dejando campos obligatorios vacíos o con un formato de correo inválido,<br>entonces el sistema bloquea el envío y muestra los mensajes de error correspondientes sin recargar la página. | EP01 |
| US04 | Sección de Casos de Éxito y Testimonios | Como Visitante del sector industrial, quiero revisar testimonios y casos de éxito de otras empresas para validar la fiabilidad y el impacto real del sistema. | **Escenario 1 (Visualización Exitosa - Happy Path):**<br>Dado que el visitante busca referencias de la industria,<br>cuando accede a la sección de testimonios,<br>entonces el sistema despliega las reseñas verificadas y los indicadores de mejora de clientes previos.<br><br>**Escenario 2 (Fallo en carga de datos - Unhappy Path):**<br>Dado que el visitante accede a la sección de testimonios,<br>cuando el servidor no logra recuperar la información externa,<br>entonces el sistema oculta la sección temporalmente y registra el error sin interrumpir la navegación general. | EP01 |
| US05 | Visualización de Planes y Tarifas de Suscripción | Como Visitante del segmento PyME o Corporativo, quiero ver los diferentes planes de precios para presupuestar la implementación del sistema según el tamaño de mi planta. | **Escenario 1 (Visualización Base - Happy Path):**<br>Dado que el visitante consulta los costos del servicio,<br>cuando el sistema detecta la consulta de tarifas,<br>entonces muestra el desglose de precios mensuales, límites de dispositivos IoT y características incluidas por cada plan.<br><br>**Escenario 2 (Cálculo de Descuento Anual - Alternative Path):**<br>Dado que el visitante evalúa opciones de pago a largo plazo,<br>cuando selecciona la modalidad de facturación anual,<br>entonces el sistema calcula y muestra dinámicamente los precios reducidos reflejando el porcentaje de descuento por año. | EP01 |
| US06 | Sección de Preguntas Frecuentes (FAQ) | Como Visitante nuevo en la plataforma, quiero acceder a una sección de preguntas frecuentes para resolver dudas inmediatas sobre la instalación, compatibilidad IoT y soporte. | **Escenario 1 (Búsqueda Exitosa - Happy Path):**<br>Dado que el visitante tiene dudas sobre los requisitos de infraestructura,<br>cuando interactúa con la sección de soporte informativo,<br>entonces el sistema provee las respuestas estandarizadas a las consultas técnicas más habituales.<br><br>**Escenario 2 (Consulta sin resultados - Unhappy Path):**<br>Dado que el visitante utiliza la barra de búsqueda de las FAQ,<br>cuando ingresa un término que no coincide con ninguna respuesta,<br>entonces el sistema muestra el mensaje "No se encontraron resultados" y proporciona un enlace directo al formulario de contacto. | EP01 |
| EP02 | Gestión de Control de Calidad y Producción Farmacéutica | Epic que consolida las operaciones de control de procesos, trazabilidad de lotes, gestión de desviaciones y cumplimiento de BPM de la plataforma. | N/A | N/A |
| US07 | Gestión y Control Digital de Protocolos de Calidad | Como Especialista de Aseguramiento y Control de Calidad, quiero registrar y estandarizar los protocolos digitales de calidad para asegurar que la producción cumpla con las normativas vigentes. | **Escenario 1 (Creación Exitosa - Happy Path):**<br>Dado que el especialista inicia la creación de un nuevo estándar con datos válidos,<br>cuando el sistema procesa la solicitud,<br>entonces almacena el protocolo en estado "Borrador" y genera un historial de versiones.<br><br>**Escenario 2 (Código Duplicado - Unhappy Path):**<br>Dado que el especialista intenta registrar un protocolo,<br>cuando el sistema detecta que el código del documento ya existe en la base de datos,<br>entonces bloquea el guardado y muestra una alerta indicando que el código debe ser único. | EP02 |
| US08 | Registro y Trazabilidad Centralizada de Lotes | Como Jefe o Supervisor de Producción Farmacéutica, quiero centralizar el expediente y el historial de cada lote de manufactura para mantener la trazabilidad completa de su ciclo de vida. | **Escenario 1 (Apertura Exitosa - Happy Path):**<br>Dado que la planta inicia una orden de fabricación,<br>cuando el supervisor asocia un protocolo vigente al nuevo lote,<br>entonces el sistema genera el código de trazabilidad único y establece el estado del lote en "En Proceso".<br><br>**Escenario 2 (Protocolo Inválido - Unhappy Path):**<br>Dado que el supervisor intenta abrir una orden de fabricación,<br>cuando asocia un protocolo que está en estado "Borrador" o "Obsoleto",<br>entonces el sistema impide la creación del lote y exige seleccionar un protocolo "Vigente". | EP02 |
| US09 | Muestreo Automatizado según Tabla Militar Estándar | Como Especialista de Aseguramiento y Control de Calidad, quiero que el sistema calcule el tamaño de muestra requerido para optimizar el tiempo de auditoría según normas estadísticas del sector. | **Escenario 1 (Aprobación de Lote - Happy Path):**<br>Dado que se ingresan los resultados analíticos de las muestras extraídas,<br>cuando el número de defectos encontrados se mantiene dentro del límite de aceptación definido,<br>entonces el sistema actualiza automáticamente el estado global del lote a "Aprobado" para su liberación.<br><br>**Escenario 2 (Rechazo de Lote por Defectos - Unhappy Path):**<br>Dado que se ingresan los resultados analíticos de las muestras,<br>cuando el número de defectos supera el límite de rechazo de la Tabla Militar,<br>entonces el sistema actualiza el estado del lote a "Rechazado" y emite una alerta crítica. | EP02 |
| US10 | Monitoreo de Telemetría e Integración IoT en Línea | Como Jefe o Supervisor de Producción Farmacéutica, quiero integrar las lecturas automáticas de los sensores de maquinaria para robustecer la integridad de los datos de fabricación sin intervención manual. | **Escenario 1 (Almacenamiento Normal - Happy Path):**<br>Dado que la línea de producción se encuentra activa y vinculada a un lote,<br>cuando los dispositivos IoT transmiten variables críticas dentro de los rangos normales,<br>entonces el sistema indexa y almacena cronológicamente cada lectura en el expediente digital del lote en curso sin interrumpir el proceso.<br><br>**Escenario 2 (Activación de Alertas - Unhappy Path Operativo):**<br>Dado que el sistema procesa lecturas en tiempo real,<br>cuando un parámetro de los sensores supera los límites críticos de tolerancia configurados,<br>entonces el sistema genera de forma inmediata una alerta de desviación operativa y despacha una notificación de urgencia al supervisor. | EP02 |
| US11 | Gestión y Registro de Desviaciones y Eventos de Calidad | Como Especialista de Aseguramiento y Control de Calidad, quiero registrar y documentar cualquier evento imprevisto o desviación detectada para mitigar los riesgos de contaminación y cumplir con las auditorías. | **Escenario 1 (Apertura y Retención - Alternative Path):**<br>Dado que se detecta una anomalía en un parámetro operativo o de muestra,<br>cuando el especialista documenta la no conformidad en la plataforma,<br>entonces el sistema cambia el estado del lote afectado a "Retenido" y congela cualquier intento de liberación logística.<br><br>**Escenario 2 (Cierre CAPA - Happy Path):**<br>Dado que una desviación se encuentra bajo investigación,<br>cuando el usuario ingresa la justificación técnica y las acciones correctivas aplicadas,<br>entonces el sistema registra la resolución, levanta la retención del lote y archiva el evento con firma electrónica. | EP02 |
| US12 | Panel de Control (Dashboard) e Indicadores de Cumplimiento | Como Supervisor de Producción, quiero visualizar gráficos unificados con el estado de los procesos y tasas de aprobación para tomar decisiones operativas oportunas y agilizar la preparación de auditorías. | **Escenario 1 (Consolidación de Métricas - Happy Path):**<br>Dado que el supervisor ingresa al panel principal,<br>cuando el sistema compila los datos históricos de las últimas operaciones,<br>entonces calcula y presenta los indicadores clave de rendimiento, el porcentaje de lotes aprobados y el volumen de desviaciones activas.<br><br>**Escenario 2 (Filtro sin resultados - Unhappy Path):**<br>Dado que un auditor externo inspecciona la planta,<br>cuando aplica un filtro de fechas donde no hubo producción registrada,<br>entonces el sistema muestra un panel vacío con el mensaje "No existen registros para el rango seleccionado". | EP02 |
| US13 | Gestión de Roles y Permisos basados en Firmas Electrónicas | Como Administrador del Sistema, quiero gestionar los accesos y roles del personal de la planta para garantizar la integridad de los datos y cumplir con las normativas de seguridad digital farmacéutica. | **Escenario 1 (Validación Exitosa - Happy Path):**<br>Dado que un especialista con rol permitido aprueba un cambio de estado,<br>cuando el sistema solicita la confirmación de la firma digital (Doble Factor),<br>entonces valida las credenciales y aplica de manera permanente el cambio en la base de datos.<br><br>**Escenario 2 (Control de Acceso Denegado - Unhappy Path):**<br>Dado que un usuario sin privilegios intenta realizar una acción crítica como liberar un lote,<br>cuando el sistema verifica que su rol no posee los permisos de firma digital autorizados,<br>entonces deniega la acción y registra un intento de acceso no autorizado en la bitácora. | EP02 |
| US14 | Registro de Auditoría Inalterable (Audit Trail) | Como Especialista de Aseguramiento de Calidad, quiero que el sistema registre de forma automática e irreversible cualquier cambio en los datos para asegurar la trazabilidad exigida por los inspectores regulatorios. | **Escenario 1 (Registro Automático - Happy Path):**<br>Dado que un supervisor modifica un parámetro operativo dentro de una orden de producción,<br>cuando el sistema detecta la edición,<br>entonces guarda automáticamente el valor anterior, el valor nuevo, el usuario responsable, la fecha y la hora exacta del cambio.<br><br>**Escenario 2 (Intento de Manipulación - Unhappy Path):**<br>Dado que se genera una traza de auditoría en la plataforma,<br>cuando un usuario (incluso con privilegios de administrador) intenta borrar o modificar dicho registro cronológico,<br>entonces el sistema bloquea permanentemente la operación y emite una alerta crítica de seguridad inmutable. | EP02 |
| US15 | Gestión del Catálogo de Productos y Fórmulas Maestras | Como Director de Producción, quiero registrar los productos farmacéuticos y sus fórmulas maestras de composición para asegurar que cada lote se fabrique con las especificaciones exactas autorizadas. | **Escenario 1 (Registro de Fórmula - Happy Path):**<br>Dado que el usuario inicia el registro de un nuevo fármaco,<br>cuando ingresa los componentes activos, excipientes y tolerancias permitidas válidas,<br>entonces el sistema almacena la fórmula en estado "Por Validar" y la vincula al catálogo oficial.<br><br>**Escenario 2 (Relación Inválida - Unhappy Path):**<br>Dado que se intenta abrir una orden de producción para un fármaco,<br>cuando el sistema detecta que su fórmula maestra asociada no se encuentra en estado "Aprobada",<br>entonces impide la creación del lote y solicita la regularización de la fórmula. | EP02 |
| US16 | Gestión de Alertas y Calibración de Dispositivos IoT | Como Supervisor de Producción, quiero administrar el estado y la calibración de los sensores IoT para garantizar que las mediciones de telemetría recopiladas en la línea sean fidedignas. | **Escenario 1 (Reconexión y Calibración Exitosa - Happy Path):**<br>Dado que un sensor recibe mantenimiento,<br>cuando el supervisor actualiza la fecha de calibración a una fecha vigente en el sistema,<br>entonces el dispositivo cambia a estado "Activo" y sus lecturas vuelven a ser procesadas en la orden de producción.<br><br>**Escenario 2 (Alerta por Descalibración - Unhappy Path):**<br>Dado que un dispositivo IoT se encuentra transmitiendo datos en la línea,<br>cuando el sistema detecta que la fecha de calibración obligatoria del equipo ha expirado,<br>entonces marca las lecturas del sensor con una etiqueta de advertencia y notifica al área de mantenimiento sin detener la línea abruptamente. | EP02 |
| EP03 | API RESTful y Servicios de Integración Backend | Epic que agrupa los endpoints y servicios técnicos necesarios para soportar la lógica de negocio, la ingesta de datos IoT y la seguridad del sistema. | N/A | N/A |
| TS01 | Ingesta de Telemetría IoT mediante Endpoint | Como Developer, quiero implementar un endpoint POST seguro para recibir las mediciones de los sensores IoT y registrarlas en la base de datos para habilitar el monitoreo en tiempo real. | **Escenario 1 (Request Exitoso - Happy Path):**<br>Dado que el dispositivo IoT envía un request POST válido con el payload de temperatura y presión,<br>cuando el API procesa la solicitud,<br>entonces devuelve un response `201 Created` y guarda el registro asociado al código del lote activo.<br><br>**Escenario 2 (Payload Inválido - Unhappy Path):**<br>Dado que el dispositivo envía un request con formato JSON malformado o variables nulas,<br>cuando el API valida el payload,<br>entonces devuelve un response `400 Bad Request` indicando el error de sintaxis y rechaza la inserción. | EP03 |
| TS02 | Autenticación y Generación de Token JWT | Como Developer, quiero implementar un servicio de autenticación para validar las credenciales de los usuarios y emitir un token JWT que proteja las rutas privadas. | **Escenario 1 (Credenciales Válidas - Happy Path):**<br>Dado que el cliente envía un request POST con email y contraseña correctos,<br>cuando el servicio valida la identidad contra la base de datos,<br>entonces devuelve un response `200 OK` adjuntando un token JWT firmado y los permisos del rol.<br><br>**Escenario 2 (Acceso Denegado - Unhappy Path):**<br>Dado que se envía un request a un endpoint protegido sin el header de autorización o con un token expirado,<br>cuando el middleware intercepta la solicitud,<br>entonces devuelve un response `401 Unauthorized` bloqueando el acceso al controlador. | EP03 |
| TS03 | Endpoint para Trazabilidad y Audit Trail | Como Developer, quiero desarrollar un endpoint GET parametrizado que exponga el historial inmutable de un lote para que el dashboard pueda renderizar las auditorías. | **Escenario 1 (Consulta de Lote Existente - Happy Path):**<br>Dado que el cliente envía un request GET con un ID de lote válido,<br>cuando el API consulta la base de datos relacional,<br>entonces devuelve un response `200 OK` con un array JSON ordenado cronológicamente con todos los eventos de dicho lote.<br><br>**Escenario 2 (Lote No Encontrado - Unhappy Path):**<br>Dado que se envía un request GET con un ID de lote inexistente,<br>cuando el servicio realiza la búsqueda,<br>entonces devuelve un response `404 Not Found` con un mensaje indicando que el registro no existe. | EP03 |
| TS04 | Endpoint para Cambio de Estado de Lote | Como Developer, quiero implementar un endpoint PATCH para actualizar el estado del ciclo de vida de un lote (ej. de "En Cuarentena" a "Aprobado") validando las reglas de negocio. | **Escenario 1 (Actualización Exitosa - Happy Path):**<br>Dado que el cliente con rol autorizado envía un request PATCH para liberar el lote,<br>cuando el API verifica que no existen desviaciones activas pendientes,<br>entonces devuelve un response `200 OK` y actualiza el estado en la base de datos.<br><br>**Escenario 2 (Regla de Negocio Incumplida - Unhappy Path):**<br>Dado que se intenta aprobar un lote que tiene alertas críticas sin resolver,<br>cuando el servicio valida las condiciones previas,<br>entonces devuelve un response `409 Conflict` detallando que el lote no puede cambiar de estado. | EP03 |
